1. How an agent should execute this cleanup plan

mtree parses a .m file into MATLAB's own syntax tree, and tree2str prints it back in canonical form: comments stripped, whitespace/bracket spacing normalised, missing end supplied.

canon = @(f) tree2str(mtree(f,'-file'));

This gives a fingerprint blind to exactly what stage 1 is allowed to change, sensitive to everything else. Verify it succeeds on all 74 in-scope files before relying on it in a tranche.

Reverse-rename check: clean a file (renames, header, reflow), then undo the rename map on the canonical form of the new file and assert it's identical to the canonical form of the old one:

c_new = canon(new_file);
for k = 1:size(renames,1)   % renames = {new_name, old_name}
    c_new = regexprep(c_new, ['(?<![A-Za-z0-9_.])' renames{k,1} '(?![A-Za-z0-9_])'], renames{k,2});
end
isequal(canon(old_file), c_new)   % must be true

The lookahead (?![A-Za-z0-9_]) matters: without it a short name (patch) can wrongly match inside a longer one (patch_size). The rename map itself must be a bijection with disjoint domain/range — assert this before using it:

dom = renames(:,1); ran = renames(:,2);
assert(numel(unique(dom)) == numel(dom));
assert(numel(unique(ran)) == numel(ran));
assert(isempty(intersect(dom, ran)));

Caveat: mtree/tree2str are undocumented MATLAB APIs — pin the MATLAB version (R2024b, per the survey) in every commit that depends on this check.

Five decisions, each of which binds any later harness extension:

  • H-1. A function with no runnable path is covered by the identity of the error it raises, not skipped. edge_props_stim (both paths) and rs_new all die before assigning an output. Recording err.identifier pins where each one fails, so a Stage 2 edit to those files cannot silently move the failure — which is precisely what Stage 2's runtime check is for. The error_id helper also records '' if the call unexpectedly succeeds, so a later fix makes replay fail loudly rather than pass quietly. This is not output coverage and is not claimed as such: the numbers those functions would return stay unverified until Stage 4.
  • H-2. Where a plain checksum is fixed by construction, add a position-weighted one. texture_patch imposes its own mean (lum) and SD (cont) on the patch it returns, so sum(patch, 'all') is 2048 for any 64x64 patch at lum = 0.5 — it would pass whatever pixels came back. The reduction therefore also carries sum(patch .* reshape(1:numel(patch), size(patch)), 'all'), which no reshuffle, wrong crop or wrong sheet survives. Use this wherever an entry point normalizes its own output.
  • H-3. Real-data patches are cut at fixed offsets, in raw gray levels, for everything except texture_patch itself. re/rs/rp/edge_props_stim are all documented as taking gray levels, and the efficient-coding histogram bins edge_props_stim needs were fitted on them, so the harness reads the sheet with imread and slices (1:64, 1:64) / (301:364, 201:264) — deterministic, no RNG draw, and the same shape of input simulate_discrimination.m builds. texture_patch's own normalized [0, 1] output is only ever used to test texture_patch. One sheet gives the same-texture pair and a second sheet the different-texture pair, so each decision variable is exercised on both conditions rather than one arbitrary call.

Parameters are chosen so the call cannot trip a bug that is already filed. re's gradient-magnitude threshold is 50 on purpose: at 20 these patches give patch 1 more contours than patch 2, and re.m's patch-2 loop runs to patch 1's contour count (B1.2), so the call dies on an out-of-range index. Verified by trying both. Same precaution the existing find_bin sweep takes around B3.2 — the harness records current behaviour, so it must not be sized to sit on top of a known crash.

The harness skips that: it would add a cross-repo dependency to every replay without changing what is being pinned, since the entry point under test is edge_props_stim, not the filter.
